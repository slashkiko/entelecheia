# 判断ログ

**案を設計に照らして判定した結果を、1件1ファイルで残す。採用も却下も同じ形で書く。**
同じ案が半年後にもう一度出たとき、そのとき何を理由に決めたかが読めることが目的になる。

## `design.md` との住み分け

同じことを2箇所に書かない（`AGENTS.md`）。3つは扱う対象が違う。

| 置き場 | 扱うもの |
|---|---|
| `docs/design.md` §3 中核の設計判断 | **既に採用され、崩すと設計全体が崩れる**判断 |
| `docs/design.md` §10 未決事項 | **まだ決まっていない**論点。決まったら打ち消し線を引く |
| `docs/decisions/`（ここ） | **持ち込まれた案を判定した記録。** 却下した案が主役になる |

判定の結果 §3 や §10 の側を直すべきだと分かったら、**ここには書かず** design.md を直す。
英語版と日本語版で節番号が揃っているので、両方を直す。

このログは日本語だけで書く。`README` と `design` は読み手向けの入口なので両言語で揃えるが、
ここは作業の記録になるため、二重管理のコストに見合わない。

## 書式

ファイル名は `NNNN-短い名前.md`（例: `0002-no-wait-flag.md`）。番号は連番で、欠番を作らない。

```markdown
# NNNN. 一行で言い切る決定

- 日付: YYYY-MM-DD
- 状態: 採用 | 却下 | 保留 | 差し替え（NNNN が置き換えた）

## 何を決めたか
（決定そのもの。1〜3文）

## なぜそう決めたか
（design.md のどの節に照らしたか。節番号を書く。設計に無い理由で決めたなら、§10 に論点を立てる）

## 代わりに検討して落とした案
（落とした理由を添える。無いなら「無し」と書く）

## 効いてくる範囲
（この決定が縛るコード・宣言・運用。無いなら「無し」と書く）
```

## いつ書くか

**オーナー（`.claude/agents/owner.md`）の6つの問いを一度でも通した案は、結論が出た時点で書く。**
実装が終わってからではない。実装しないと決めた案こそ、書かないと消える。

書かないもの: 実装の細部（どのライブラリを使ったか、どう書いたか）。それはコードとコミット
メッセージが持つ。ここに置くのは、**別の選択肢もあり得た**判断だけになる。
