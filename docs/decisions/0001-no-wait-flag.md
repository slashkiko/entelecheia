# 0001. CLI に `--wait` を入れない

- 日付: 2026-09-07（決定そのものは `agent-friendly-cli` の宣言時。ログの起点としてここに記録する）
- 状態: 却下

## 何を決めたか

ティックの完了をコマンド側で待ち合わせる `--wait` 相当のオプションを入れない。呼び出し側が
完了を待ちたい場合は、`ent run` を繰り返し叩いて `ent get` で状態を読む。

## なぜそう決めたか

**待機はプロセスではなく状態にする（design.md §3.6）に反するため。** CLI の中でポーリングを
回すと、reconcile が有限時間で return するという性質が呼び出し側から見えなくなり、実質的に
常駐プロセスに戻る。中断可能性はそこで失われる。

`ent` の待機はすべて Goal の状態（`WAITING_HUMAN` など）として外から読めることに意味があり、
コマンドがブロックしている間はその状態を誰も読めない。

## 代わりに検討して落とした案

- **`--wait` にタイムアウトを付けて有限にする。** 有限ではあるが、待っている間の状態が
  外から読めない点は変わらない。§3.6 が守りたいのは実行時間の上限ではなく、任意の瞬間に
  kill して次のティックで拾えることになる。

## 効いてくる範囲

- CLI 全体: 完了を待ち合わせる形のオプションは、名前を変えても同じ理由で入らない
- cron と既存の検証コマンド: `--json` と `--dry-run` を渡さないときの出力と終了コードを
  変えない前提で書かれている（`.goals/agent-friendly-cli.yaml`）
