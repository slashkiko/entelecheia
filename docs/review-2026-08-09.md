## 0. この文書の読み方

指摘には ID を振ってある。`SEC` がセキュリティ、`SEM` が宣言と実装の食い違い、
`TS` が型と境界、`S` が重複と死んだコードにあたる。

部分的にしか閉じていないものは、ID に **（一部）** を付けて §1 と §5 の両方に載せる。
片方だけ読んでも状態を取り違えないようにするため。

§1 の表の「壊して確かめたか」の列は4値で、意味は次のとおり。

| 値 | 意味 |
|---|---|
| **KILL** | 直した箇所を壊して、対応するテストが落ちることを実際に確かめた |
| **別手段で確認** | ミューテーションはしていないが、テスト自体が壊れた状態を作って確かめている |
| **未実施** | テストはあるが、壊して落ちることは確かめていない |
| **対象外** | 文書の変更、または `export` キーワードの削除のみで、壊す対象が無い |

## 2. 既存テストを弱めたか

**弱めていない。** 既存テストに触れたのは3ファイルで、内訳は次のとおり。

**期待値を変えたもの（1件）** — `tests/cli-main.test.ts` の「終端の Goal は
start し直せない」。終了コードの期待値を 2 から 1 に変えた。Goal の constraints が
明示的に許した唯一の例外にあたる。

理由。`agent-context` と SKILL.md は 2 を「引数が不正。stderr に有効値が並ぶ」と
宣言している。終端 Goal への `start` は argv が妥当で、打ち直せる別の値も無い。
2 を返すと、SKILL.md に従うエージェントが argv を変えて無限に再試行できる。
**テストの主張（start が拒否されること）は変えていない。**

**スタブを実装に追随させたもの（2件）**

- `tests/github-write.test.ts` — 承認の判定に権限 API の呼び出しが増えたので、
  fake fetch に `/permission` の応答を足した。既存8本の assert はそのまま。
  拒否側3本と、通る側1本を新たに足した
- `tests/claude-adapter.test.ts` — 拒否リストの中身を逐語で固定しているテストに、
  追加した3行（`core.hooksPath` の拒否）を反映した。assert の性質は変えていない

## 4. 関門は本当に強くなったか

直した箇所を壊して、対応するテストが落ちることを確かめた。**壊し方が実際の退行を
模していれば**、落ちないテストは関門になっていない。

KILL は16件（§1 の表を参照）。壊した内容を挙げる。

- SEC1 `commandRunner` から `env` を外す
- SEC2 hooks の指紋・`core.hooksPath` の指紋・保護下限の `.git/**`（3通り）
- SEC3 状態 DB の指紋を外す
- SEC4 権限の集合判定を外す
- SEC5 `protected_paths` の transform を外す
- SEC6 slug の検証を素通しにする
- SEM1 `withConstraints` を外す
- SEM2 `preview` の `uncommittedDecision` を外す
- SEM3 dry-run の分岐を外す
- SEM4 未登録の判定を素通しにする
- SEM5 終端 start を 2 に戻す／`main()` の try/catch を外す（2通り）
- SEM7 idle の `dryRun` を外す
- TS1 正規表現を表から切り離して `[smhd]` に広げる
- TS3 `refine` を素通しにする
- TS5 `EFFORT_LEVELS` から値を1つ減らす
- S4 `errorMessage` の中身を空文字に変える

**TS1 では最初のミューテーションが生き残った。** `?? 3600` のフォールバックを
入れる壊し方をしたが、正規表現が `d` を弾くので実際には到達しない経路だった。
壊し方が実際の退行を模していなかっただけで、テストの穴ではない。「正規表現を
表から切り離す」——単位を足すときに片方だけ直す、という実際の壊れ方——に
変えたら落ちた。

生き残ったミューテーションが必ずテストの穴を意味するわけではない、という例として残す。

**未実施は7件**: SEC4（一部）/ SEM9 / TS4 / S5 / S8 / S9 / S10。
いずれもテストは存在するが、壊して落ちることは確かめていない。
