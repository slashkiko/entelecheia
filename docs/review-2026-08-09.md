## 2. 既存テストを弱めたか

弱めていない。変更したのは1ファイルで、**assert は1つも変えていない**。

`tests/github-write.test.ts` — 承認の判定に権限 API の呼び出しが増えたので、
fake fetch に `/permission` の応答を足した。既存8本の assert はそのまま。
あわせて拒否側3本（read / triage の拒否、権限が読めないときの throw、
404 のときの未承認）と、通る側1本を足した。

**弱めたのではなく、動かしたものが1件ある。** `tests/cli-main.test.ts` の
「終端の Goal は start し直せない」で、期待する終了コードを 2 から 1 に変えた。
Goal の constraints が明示的に許した唯一の例外にあたる。

理由。`agent-context` と SKILL.md は 2 を「引数が不正。stderr に有効値が並ぶ」と
宣言している。終端 Goal への `start` は argv が妥当で、打ち直せる別の値も無い。
2 を返すと、SKILL.md に従うエージェントが argv を変えて無限に再試行できる。
assert の向きは変えていない（「拒否される」ことは同じ）。合わせて、`main()` が
実際に返す全コードが `agent-context` に載っていることを見るテストを足した。

## 3. 検証コマンドの結果

最終コミット時点で全段が通る。

```

mise run lint        0 違反（追加した7ルール込み）
mise run build       dist/cli.js を生成
mise run test        52ファイル 543テスト 全通過
```

追加した `noFloatingPromises` が実際に1件捕まえた。`main()` の契約を閉じたときに
書いたエントリの `.then(...)` で、`void` を付けて明示した。0違反のルールを
足しても意味が無いわけではない、という実例になる。

`mise run check` はこの環境で未実行。`mise install` が無関係な global の flutter で
落ちるため。shellcheck だけはインストール済みのパスから直接流して 0 件を確認した。
CI（`verify.yml`）では `mise-action` が入れるので、ac-5 の CI で確かめることになる。

## 4. 関門は本当に強くなったか

直した箇所を壊して、対応するテストが落ちることを確認した。落ちないなら、そのテストは
関門になっていない。

確認した8件はすべて KILL（壊すと落ちる）。

- SEC1 `commandRunner` から `env` を外す → 落ちる
- SEC4 権限の集合判定を外す → 落ちる
- SEC5 `protected_paths` の transform を外す → 落ちる
- SEC6 slug の検証を素通しにする → 落ちる
- SEM1 `withConstraints` を外す → 落ちる
- SEM2 `preview` の `uncommittedDecision` を外す → 落ちる
- SEM3 dry-run の分岐を外す → 落ちる
- SEM4 未登録の判定を素通しにする → 落ちる
- SEM7 idle の `dryRun` を外す → 落ちる
- TS1 正規表現を表から切り離して `[smhd]` に広げる → 落ちる
- TS3 `refine` を素通しにする → 落ちる

**TS1 では最初のミューテーションが生き残った。** `?? 3600` のフォールバックを入れる
壊し方をしたが、正規表現が `d` を弾くので実際には到達しない経路だった。壊し方が
実際の退行を模していなかっただけで、テストの穴ではない。正規表現を表から切り離す
——「単位を足すとき片方だけ直す」という実際の壊れ方——に変えたら落ちた。

生き残ったミューテーションが必ずテストの穴を意味するわけではない、という例として残す。

**未実施**: SEM6 / SEM9 / TS2 / TS4 / S9。TS2 は実 DB の列を改名して落ちることを
テスト自体で確かめているので、実質ミューテーションに相当する。
